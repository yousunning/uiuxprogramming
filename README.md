# UI/UX Programming

## 프로젝트 소개

### 오늘 뭐 입지?

날씨와 상황에 맞는 옷차림을 간편하게 추천받을 수 있는 서비스입니다.

매일 어떤 옷을 입을지 고민하는 사용자가 자신의 상황과 스타일을 입력하고,
적절한 코디를 쉽게 확인할 수 있도록 구성하는 것을 목표로 합니다.

---

# 1주차 - HTML 기본 구조 작성

## 학습 내용

HTML 문서의 기본 구조를 이해하고 첫 웹페이지를 작성했습니다.

`<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`의 역할을 확인하고
제목과 본문을 표현하기 위해 `<h1>`, `<p>` 태그를 사용했습니다.

## 구현 내용

- HTML 기본 문서 구조 작성
- 페이지 제목 작성
- 서비스 이름과 간단한 소개 문구 작성
- 브라우저에서 HTML 페이지 실행 및 확인
- Git을 이용한 작업 내용 저장

## 서비스 주제

서비스 이름을 `오늘 뭐 입지?`로 정하고,
날씨와 상황에 맞는 옷차림을 추천하는 서비스를 주제로 선정했습니다.

---

# 2주차 - HTML 시맨틱 구조와 내부 이동

## UX 계획

- 사용자: 날씨와 일정에 맞는 옷차림을 고민하는 사람
- 목적: 상황과 날씨에 적합한 옷차림을 쉽고 빠르게 확인한다.
- 핵심 행동: 오늘의 상황을 입력하고 추천 코디를 확인한다.
- 정보 순서: 서비스 소개 → 주요 기능 → 이용 방법 → 코디 추천 받기

## 구현 내용

1주차에 작성한 `index.html`을 기반으로 서비스 정보를 확장했습니다.

- `<header>`를 이용해 서비스 이름과 소개 영역 구성
- `<nav>`를 이용해 페이지 내부 이동 메뉴 구성
- `<main>`과 `<section>`을 이용해 콘텐츠 영역 구분
- `<ul>`을 이용해 주요 기능 3개 구성
- `<ol>`을 이용해 서비스 이용 순서 표현
- `<img>`와 `alt` 속성을 이용해 서비스 이미지 추가
- `<form>`, `<label>`, `<input>`, `<button>`을 이용해 입력 영역 구성
- `<footer>`를 이용해 페이지 하단 정보 구성

## 구조 변경 이유

1주차에는 서비스 이름과 간단한 설명만 존재했기 때문에
사용자가 서비스의 기능과 이용 방법을 한눈에 파악하기 어려웠습니다.

2주차에는 콘텐츠를 서비스 소개, 주요 기능, 이용 방법,
코디 추천 영역으로 나누어 정보의 순서를 명확하게 구성했습니다.

또한 내비게이션 링크와 각 section의 id를 연결하여
사용자가 원하는 영역으로 바로 이동할 수 있도록 개선했습니다.

## 직접 작성한 HTML과 AI 생성 HTML 비교

직접 작성한 HTML은 수업에서 학습한 태그를 중심으로
기본적인 콘텐츠 구조를 구성하는 데 초점을 맞췄습니다.

AI를 활용해 비교한 HTML에서는
`header`, `nav`, `main`, `section`, `footer`와 같은
시맨틱 요소를 이용해 각 콘텐츠의 역할을 더 명확하게 구분할 수 있었습니다.

또한 이미지의 `alt` 속성, `label`과 `input`의 연결,
내비게이션의 `aria-label` 등 접근성을 고려할 수 있는 요소의 차이를 확인했습니다.

비교를 통해 화면에 콘텐츠를 단순히 배치하는 것뿐만 아니라
정보의 위계와 의미, 사용자의 이동 흐름을 고려하여
HTML 구조를 작성하는 것이 중요하다는 점을 확인했습니다.

# 3주차 - CSS 정보 위계와 상태 피드백

## 학습 내용

HTML로 구성한 서비스에 외부 CSS를 연결하고,
색상, 글자 크기, 여백, 박스 모델과 Flexbox를 이용해
정보의 시각적 위계를 표현했습니다.

또한 `hover`, `focus`, `active`, `transition`을 적용하여
사용자의 조작에 대한 상태 변화를 확인할 수 있도록 했습니다.

## 구현 내용

- `style.css` 생성 및 `index.html`에 외부 CSS 연결
- 전체 콘텐츠의 최대 너비와 기본 여백 설정
- 제목과 본문의 크기 및 굵기를 구분하여 정보 위계 표현
- 서비스 소개 영역에 Flexbox 적용
- 주요 기능 3개를 카드 형태로 구성
- 주요 기능 카드에 동일한 간격과 배경 적용
- 이용 방법 목록의 간격 조정
- 오늘의 상황 입력창 추가
- 이메일 입력창과 주요 버튼을 한 줄로 배치
- 입력창에 `focus` 상태 적용
- 주요 버튼에 `hover`, `focus`, `active`, `transition` 적용
- footer 스타일 적용

## 대표 CSS 수정 내용

이메일 입력창과 코디 추천 버튼을 하나의 행동 영역으로 구성하기 위해
`.subscribe-form`에 Flexbox를 적용했습니다.

```css
.subscribe-form {
  display: flex;
  align-items: flex-end;
  gap: 12px;
}
```

# 4주차 - 반응형 웹페이지 구현

## 확인한 문제

3주차 페이지는 넓은 화면을 기준으로 구성되어 있어
화면 너비가 좁아질 경우 메뉴와 입력 영역이 답답해지고,
기능 카드의 너비가 지나치게 좁아지는 문제가 있었습니다.

특히 390px 모바일 화면에서 가로로 배치된 요소들을
사용하기 불편할 수 있다는 점을 확인했습니다.

## 수정한 내용

- 전체 콘텐츠에 `width: 100%`와 `max-width` 적용
- 내비게이션에 `flex-wrap` 적용
- 서비스 이미지에 유동 너비 적용
- 기능 카드 목록을 Flexbox에서 Grid로 변경
- `auto-fit`과 `minmax()`를 이용해 화면 너비에 따라 카드 열 자동 조정
- 768px 이하에서 내비게이션을 세로로 변경
- 768px 이하에서 기능 카드를 한 열로 변경
- 768px 이하에서 이메일 입력창과 버튼을 세로로 변경
- 모바일 환경에서 버튼의 최소 높이를 48px로 설정

## 반응형 기준

`@media (max-width: 768px)`을 사용하여
768px 이하에서는 모바일 환경에 적합한 한 열 구조가
적용되도록 구성했습니다.

769px에서는 기본 레이아웃이 유지되고,
768px부터 메뉴, 카드, 폼의 배치가 변경되는 것을 확인했습니다.

## 달라진 점

1100px에서는 넓은 화면을 활용해 콘텐츠가 여러 열로 표시되고,
768px 이하에서는 메뉴와 기능 카드, 입력 영역이 한 열로 재배치됩니다.

390px에서도 가로 스크롤이나 콘텐츠 잘림 없이
서비스의 내용을 확인하고 입력 기능을 사용할 수 있도록 개선했습니다.

## 사용자 이점

화면 크기에 따라 콘텐츠가 자동으로 재배치되어
PC와 모바일 환경 모두에서 서비스의 내용을 쉽게 확인할 수 있습니다.

특히 모바일에서는 입력창과 버튼을 세로로 배치하여
좁은 화면에서도 주요 기능을 편리하게 사용할 수 있도록 개선했습니다.

# 5주차 - JavaScript로 화면에 피드백 주기

## 1. 구현 목표

기존 HTML과 CSS로 구성한 정적 웹페이지에 JavaScript를 연결하여
사용자의 클릭에 따라 화면이 변경되는 기능을 구현했습니다.

서비스 주제인 '오늘 뭐 입지?'에 맞춰
코디 추천 알림 설정 기능을 추가했습니다.

## 2. 구현 내용

### JavaScript 파일 연결

- script.js 파일 생성
- index.html의 body 종료 태그 바로 위에 JavaScript 연결

### DOM 요소 선택

- querySelector()로 저장 버튼과 안내 문구 선택
- HTML의 id와 JavaScript 선택자를 연결

### 클릭 이벤트 구현

- addEventListener()를 이용한 클릭 이벤트 처리
- 저장 버튼 클릭 시 saveSettings() 함수 실행

### 화면 피드백 구현

- textContent로 안내 문구 변경
- classList.add()로 저장 완료 스타일 적용
- 버튼 문구를 '설정 완료'로 변경
- disabled 속성을 이용해 중복 클릭 방지

## 3. 화면 변화

### 변경 전

- 안내 문구: 코디 추천 알림을 설정해 주세요.
- 버튼 문구: 알림 설정 저장
- 버튼 상태: 활성화

### 변경 후

- 안내 문구: 코디 추천 알림 설정이 완료되었습니다.
- 안내 문구 배경: 초록색
- 버튼 문구: 설정 완료
- 버튼 상태: 비활성화

## 4. 사용자 이점

사용자가 알림 설정 버튼을 클릭하면
문구와 색상, 버튼 상태가 함께 변경됩니다.

이를 통해 사용자는 자신의 조작이 정상적으로 처리되었는지
화면에서 즉시 확인할 수 있습니다.

또한 설정 완료 후 버튼을 비활성화하여
동일한 동작을 반복하지 않도록 구성했습니다.

# 6주차 - 이벤트와 동적 UI 구현

## 1. 구현 목표

5주차에 구현한 JavaScript 클릭 이벤트를 확장하여
사용자 입력과 선택에 따라 화면이 실시간으로 변경되는 기능을 구현했습니다.

서비스 '오늘 뭐 입지?'에 맞춰 화면 테마 변경,
사용자 이름 입력, 서비스 이용 확인, 코디 추천 탭 UI를 추가했습니다.

## 2. 구현 내용

### click 이벤트

- 테마 변경 버튼 클릭 시 밝은 테마와 어두운 테마 전환
- body의 dark 클래스 추가 및 제거
- 현재 테마에 맞춰 버튼 문구 변경

### input 이벤트

- 사용자 이름 입력 시 글자 수 실시간 표시
- maxlength 속성으로 최대 10자 제한
- textContent로 글자 수 안내 문구 변경

### change 이벤트

- 이용 안내 체크박스 선택 여부 확인
- 체크 시 시작 버튼 활성화
- 체크 해제 시 시작 버튼 비활성화
- 안내 문구와 스타일 동시 변경

### 탭 UI

- 날씨별 코디
- 상황별 코디
- 간편한 코디 선택

querySelectorAll()과 forEach()로 여러 탭에 이벤트를 연결하고,
data-target으로 각 탭과 콘텐츠를 연결했습니다.

## 3. 화면 변화

- 테마 버튼 클릭 시 화면 배경과 버튼 문구 변경
- 사용자 이름 입력 시 글자 수 즉시 변경
- 체크박스 선택 시 안내 문구와 시작 버튼 상태 변경
- 탭 클릭 시 선택한 콘텐츠만 표시

## 4. 사용자 이점

사용자가 수행한 행동에 따라 화면이 즉시 반응하도록 구성했습니다.

입력 상태와 선택 결과를 명확하게 표시하여
사용자가 현재 상태를 쉽게 이해할 수 있도록 개선했습니다.

또한 탭 UI를 통해 원하는 코디 추천 정보를
페이지 이동 없이 확인할 수 있도록 구성했습니다.
